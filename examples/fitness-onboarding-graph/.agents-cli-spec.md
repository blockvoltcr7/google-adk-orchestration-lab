# Agent Spec

## Overview

This lesson rebuilds the qualified fitness-client onboarding example as an
explicit Google ADK graph workflow:

```text
START -> validate intake
              | valid   -> consultation agent -> booking node
              |          -> welcome agent -> email node -> confirmation
              |
              | invalid -> correction response
```

The client is already qualified before entering this workflow. Budget
qualification belongs in the separate conditional-routing lesson.

## Input

The workflow accepts a JSON object in the user's message with:

- `name`
- `email`
- `primary_goal`
- `experience_level`
- `availability`
- `physical_constraints`
- `preferred_consultation_time`

## Graph Nodes

1. `validate_intake` parses, validates, and normalizes the submitted JSON.
2. Invalid input routes directly to `render_intake_correction`.
3. Valid input routes to `consultation_agent`, which creates a typed plan.
4. `create_booking` creates a deterministic local booking result.
5. `welcome_agent` creates a typed welcome-email draft.
6. `send_email` records a deterministic local delivery result.
7. `render_onboarding_confirmation` emits the user-visible result.

## Safety and Local-Only Constraints

- Do not diagnose medical conditions or prescribe treatment.
- Do not invent missing client details.
- Preserve physical constraints in downstream outputs.
- Do not send real email or create a real appointment.
- Do not call an external booking, email, database, or CRM service.
- Invalid input must have no graph path to booking or email nodes.
- Never store secrets or real client information in source, tests, traces, or
  documentation.

## Success Criteria

- A complete intake follows the valid route in the documented order.
- An incomplete intake follows only the invalid route.
- Node boundaries use typed Pydantic contracts.
- LLM nodes use structured outputs and contain no tools.
- Booking and email nodes are deterministic and JSON serializable.
- The ADK web UI receives a user-visible content event at either terminal node.
- Unit tests, integration tests, lint, package build, smoke tests, and initial
  evaluations pass.

## Deployment Preference

This scaffold is intentionally local (`deployment_target: none`). Deployment,
cloud resources, and CI/CD require a later explicit decision.
