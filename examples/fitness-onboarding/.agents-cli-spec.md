# Agent Spec

## Overview

The qualified fitness-client onboarding agent turns a completed client intake
into a coach consultation plan, a booking link, and a welcome-email delivery
result. It teaches deterministic sequential orchestration with three Google ADK
agents:

1. The intake agent validates and normalizes the submitted form.
2. The consultation agent prepares a coach briefing and consultation plan.
3. The welcome agent creates a booking link and sends a welcome email through
   local placeholder tools.

The client is already qualified before this sequence starts. Qualification and
budget branching belong to a later conditional-routing lesson.

## Example Use Cases

### Complete qualified-client intake

Input:

```json
{
  "name": "Jordan Lee",
  "email": "jordan@example.com",
  "primary_goal": "Build consistent strength",
  "experience_level": "Beginner",
  "availability": "Monday, Wednesday, and Friday evenings",
  "physical_constraints": "Previous knee discomfort; avoid assumptions",
  "preferred_consultation_time": "Tuesday at 6:00 PM Eastern"
}
```

Expected behavior:

- Validate and normalize the intake without inventing facts.
- Create a consultation plan that retains the client's constraints.
- Create a deterministic local booking link.
- Compose and record a welcome email through the local email tool.
- Return a natural-language onboarding confirmation.

### Incomplete intake

Expected behavior:

- Record structured validation errors in session state.
- Continue through the fixed ADK sequence without invoking booking or email
  tools.
- Explain which fields must be corrected before onboarding can continue.

## Tools Required

- `validate_client_intake`: Validates and normalizes the submitted intake with
  Pydantic. No authentication or external API is required.
- `create_booking_link`: Returns a deterministic, production-shaped URL under a
  reserved example domain. No booking provider is contacted.
- `send_welcome_email`: Returns a deterministic, production-shaped delivery
  result. No email is transmitted.

## Architecture & Sub-Agents

- `intake_agent` uses the validation tool and stores `intake_summary`.
- `consultation_agent` reads validated state and stores `consultation_plan`.
- `welcome_agent` uses the booking and email tools and stores
  `onboarding_response`.
- `fitness_onboarding_agent` is a `SequentialAgent` that always enters the
  three agents in that order.
- Prompts are versioned YAML resources and are loaded by a validated prompt
  loader.
- Builder classes return fresh ADK agent instances for safe composition.

## Constraints & Safety Rules

- Do not diagnose medical conditions or prescribe treatment.
- Do not invent missing client details.
- Preserve reported physical constraints in downstream outputs.
- Do not send real email, create a real appointment, access a database, or call
  any external service.
- Do not store secrets, credentials, or real client information in source,
  tests, screenshots, traces, or documentation.
- Invalid intake must not invoke booking or email tools.

## Success Criteria

- All three agents execute in the documented order for a complete intake.
- Downstream agents consume state produced by earlier stages.
- Complete intake invokes validation, booking, and email tools in order.
- Incomplete intake reports validation errors and does not invoke booking or
  email tools.
- Client facts and physical constraints remain present without fabrication.
- The final response contains no diagnosis or medical-treatment advice.
- Unit tests, integration tests, lint, package build, smoke tests, and the
  initial evaluation cases pass.

## Reference Samples

No catalog sample directly matches this small fixed-sequence lesson. The
implementation follows the installed Google ADK `SequentialAgent`, function
tool, session-state, and `App` APIs.

## Deployment Preference

Develop and verify locally first. The existing scaffold targets Agent Runtime,
but deployment, cloud resources, and CI/CD are outside this implementation
slice and require separate approval.
